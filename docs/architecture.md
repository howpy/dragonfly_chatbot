# 资料库与查询设计

## 首版实现进度（2026-10-21）

已实现 Harness bundle、BM25＋中文术语补充检索、严格版本过滤、三个只读工具、
证据行号、本地导入与合并 CLI；内置 112 个扩展的 162 份手册。真实 Harness 的
工具执行、提示词组装与卸载验证通过。下文保留目标架构与后续路线；源码结构切分、
稠密检索和跨模型准确率评测仍属后续工作，当前按有重叠且大小受限的文本窗口切分。

## 范围与边界

产品名称固定为 `dragonfly_chatbot`。Harness 负责模型对话，插件负责技术资料的
查询能力与回答规则。初期只做技术问答和代码建议，不控制 Dragonfly 的运行状态。
具体当前实现和限制以 README 与 docs/verification.md 为准。

## 资料分层

| 来源 | 用途 | 初始处理 |
| --- | --- | --- |
| Dragonfly Help / 技术文档 | 操作、功能、参数 | 本地只读导入，按版本建库 |
| 已确认授权的开放源码 | API、事件、插件机制与实现 | 按仓库 revision / 软件版本索引 |
| 安装目录内可读 Python | 用户本机接口核验 | 独立本地来源，不自动认定为开源 |
| Prototype Apps manual.json | 扩展功能与安装说明 | 与官方资料分开标记 |
| Script Builder blocks / recipes | 可执行用法参考 | 保留来源与适用版本，不作为官方承诺 |

已有 Chatbot 明确不随安装包分发 Dragonfly Help。新项目沿用该边界；可读源码也
不自动等于获准再分发。可公开资料与本机专用索引分开维护。索引及向量同样不默认发布。
首版仅快照已有分发政策允许的自有插件手册；本机资料源示例配置仍全部禁用，
由用户显式导入，逐项确认来源与版本后使用。

## 导入与索引

1. 显式配置根目录与允许类型，排除凭据、日志、数据集、缓存、构建产物。
2. 文档按标题 / 章节切分，源码按模块 / 类 / 函数切分；大函数允许子切片，保留父级。
3. 每个片段记录 `source_id`、`document_id`、`chunk_id`、`kind`、`title`、
   `dragonfly_version`、`revision`、`language`、`relative_path`、`heading`、
   `symbol`、`line_start`、`line_end`、`content_sha256`、`license`、`redistribute`。
4. 使用内容哈希去重和增量更新；来源移除时撤销旧片段；稳定 ID 不依赖机器绝对路径。
5. 保留原文和可追溯定位，不把生成摘要当成原始资料。HTML 转换保留标题与代码块。
6. 本地配置保存用户资料路径；市场包不硬编码开发机器路径。

## 查询流程

用户问题 → 识别问题类型与软件版本 → 生成中英文术语 / 精确符号查询 →
按版本与来源过滤候选 → 召回 → 阅读相邻上下文 → 汇总证据 → Harness 生成带引用回答。

未知版本资料不能悄悄当作任一版本的可靠证据。跨版本问题分别召回，再比较差异。
API 查询优先精确标识符；操作查询优先帮助文档；错误查询同时检索错误文本及实现。

计划向 Harness 暴露三个只读工具：

- `search_dragonfly_knowledge(query, version?, kind?, limit?)`：返回片段 ID、来源、定位及摘录。
- `read_dragonfly_evidence(chunk_id, context_lines?)`：读取索引登记的证据与有上限的上下文。
- `get_dragonfly_corpus_status()`：返回资料版本、缺失来源和索引时间，不暴露用户完整路径。

工具仅访问登记的来源 / ID，限制查询长度、返回条数和上下文预算，拒绝路径穿越及
符号链接逃逸。不要给模型任意文件读取能力。插件权限按已验证的 Harness 接口实现。

## 优化必须经过评测

复用前阅读 `DragonflyPlugins/Chatbot-Plugin/DESIGN.md` 与检索模块的测量说明：
已有实现默认使用稠密检索，混合检索不是默认，增加候选也不保证回答更准确。
不能把旧模型、旧语料的结果当成本项目在 DeepSeek 上的成绩。

先测量精确搜索和稠密检索基线，再比较 BM25、RRF、重排及查询改写；
只在保留测试集上的回答准确率和引用正确率改善后修改默认策略。
记录模型、嵌入模型、语料哈希、版本过滤、召回数量、上下文预算、时间与成本。

初始 `evaluation/questions.jsonl` 是待补充金标准的种子集，不能用于宣称产品准确率。
正式发布前补充来源 ID / 预期证据，划分开发集与保留集；测量召回率、回答正确率、
引用支持率、版本混淆率、无证据拒答与延迟，并与冻结基线比较。

## 实施里程碑

- M0（已完成）：目录、设计、Agent 提示词、资料配置示例与评测种子。
- M1：资料盘点与授权标记、导入器、可重复构建的版本索引。
- M2：独立检索工具和评测基线，验证中文查询与英文资料匹配。
- M3：Harness 插件适配，确认模型实际调用工具并输出可打开的引用。
- M4：全新环境安装 / 升级 / 卸载、缺失资料和错误恢复测试，准备市场收录。
